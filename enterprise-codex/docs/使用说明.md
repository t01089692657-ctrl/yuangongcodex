# 使用说明（含 Mac mini 安装）

本文覆盖：在 Mac mini 上安装并启动服务端、员工如何用客户端接入、管理者如何登录后台、离职吊销、推送公司技能、常见问题。

> 术语：**网关/服务端** = 跑在 Mac mini 上的那台服务（员工连它）。**客户端** = 装在每个员工电脑上的封装（内置 Codex）。

---

## 0. 前置条件

- **Node.js ≥ 20**（建议 22）。检查：`node -v`。没有就 `brew install node`。
- 一台 **Mac mini**（或任意 macOS/Linux 机器）作为服务端，办公网内其他机器能访问它的 IP。
- **上游模型额度**：公司自有的 OpenAI 或 Azure OpenAI 的 API Key（合规做法）。想先空跑体验，可用内置的 mock 上游，不需要真 Key。

---

## 1. 在 Mac mini 上安装服务端

```bash
# 1) 拷贝并解压交付包
tar -xzf enterprise-codex.tgz
cd enterprise-codex

# 2) 生成配置（自动生成强随机密钥，写入 .env）
./scripts/setup.sh            # 试用姿态（开启邮箱模拟登录，便于先跑通）
#   或  ./scripts/setup.sh prod   # 生产姿态（仅真实飞书 SSO，Cookie 强制 Secure）

# 3) 打开 .env，把上游改成公司自己的 Key（或跳过这步，用下面的 --with-mock-upstream 先体验）
#    UPSTREAM_BASE_URL=https://api.openai.com/v1
#    UPSTREAM_API_KEY=sk-你的公司Key
nano .env

# 4) 启动
./scripts/start.sh                        # 用 .env 里的真实上游
#   或  ./scripts/start.sh --with-mock-upstream   # 不打真实 API，先跑通整条链路
```

启动后终端会打印监听地址，例如 `http://0.0.0.0:8080`。用局域网 IP 记下给员工，例如 `http://192.168.1.50:8080`（`setup.sh` 已帮你探测并写进 `GATEWAY_PUBLIC_URL`）。

> **让它常驻**：生产上用 `pm2 start gateway/server.js --name codex-gateway` 或做成 launchd 服务；试用阶段直接开着终端即可。

### 安全提示
- `.env` 含密钥，已被 `.gitignore`，`chmod 600`，**不要外传/提交**。
- **试用姿态**开启了"输入邮箱即可作为管理者登录"的模拟入口（代替真实飞书回调），**只在可信内网使用**；上线前改 `DEMO_MODE=false` 并接入真实飞书 SSO。
- 生产模式下如果密钥还是默认值，网关会**拒绝启动**并提示你更换——这是有意的保护。

## 2. 员工怎么用

有两种形态，二选一：

### 方式 A：桌面 App（推荐，视频里那种）
`desktop/` 是一个 Electron 桌面应用。员工打开后点「使用飞书登录」，浏览器完成飞书授权，App 就自动签发 Key、写好配置、同步技能，然后 **Codex 直接在 App 窗口里跑起来**（内嵌终端 xterm.js + node-pty，员工不用开终端、不用碰任何配置）。

**你（管理员）打包 .dmg（在一台 Mac 上，Mac mini 即可）：**
```bash
cd desktop
# 1) 把网关地址填进 app-config.json（员工就不用手填了）：
#    { "gatewayUrl": "http://192.168.1.50:8080", "codexBin": "" }
# 2) 把公司 Codex 二进制放到 vendor/codex/codex
npm install        # 装 Electron、编译 node-pty、内嵌 xterm
npm run dist       # 产出 dist/Company Codex-0.1.0.dmg
```

> `npm install` 会自动跑 `electron-rebuild` 让原生模块 node-pty 匹配 Electron。若 node-pty 编译不出来，App 会自动退回"用外部终端启动 Codex"，不影响使用。**注意：`.dmg` 必须在 macOS 上构建**（electron-builder 打 Mac 包需要 Mac）。

**员工安装与使用（三步，零配置）：**
1. 打开你发的 `.dmg` → 把「Company Codex」拖进「应用程序」。
2. 首次打开：**右键 →「打开」**（未签名 App 的 Gatekeeper 提示，点一次「打开」即可；你也可以提前用 `xattr` 去隔离标记或用 MDM 免提示，见 `desktop/README.md`）。
3. 点「使用飞书登录」→ 浏览器飞书授权 → 回到 App → **Codex 就在窗口里能用了**。API/技能都已自动配好，员工什么都不用填。

> 员工离职 → 网关吊销其 Key → App 里的 Codex 立刻 401 用不了。App 本身不存长期密钥。

### 方式 B：命令行客户端（同一套核心逻辑）
```bash
# 真实飞书登录（会打开浏览器）
node client/launcher.js --provider feishu \
  --gateway http://192.168.1.50:8080 \
  --codex-bin /Applications/CompanyCodex.app/.../codex

# 没配飞书时的离线自测：
node client/launcher.js --provider mock --email 你@corp.com --gateway http://192.168.1.50:8080 --simulate
```

- 省略 `--codex-bin`（或加 `--simulate`）时，客户端会**发一条验证请求**证明链路通了，不真正拉起 Codex——适合自测。
- 配置写到**受管目录**（默认 `~/.codex-managed`，用 `CODEX_HOME` 指向），不污染员工自己的 `~/.codex`。
- 桌面 App 和命令行都调用同一个 `client/core.js`；`npm run demo-feishu` 会离线跑通整条真实飞书 OAuth 链路。

员工机器上生成的东西（示例）：
```
~/.codex-managed/
├── config.toml     # model_provider=mycompany, base_url=网关, wire_api=responses
├── auth.json       # 注入的 Key
├── AGENTS.md       # 公司规范（自动同步）
└── prompts/        # 公司斜杠命令（自动同步）
```

## 3. 管理者后台

浏览器打开网关地址：`http://192.168.1.50:8080/`

- 会看到**登录页**。管理者用公司账号登录（试用姿态下输入管理者邮箱即可，如 `alice@corp.com`）。
- **普通员工登录会被拒（403）** —— 这就是管理者与员工的区分。
- 登录后可见：**用量排行榜**（每人 token 数、请求数、角色、在职状态）、**一键吊销**入口（吊销会记录操作人）。
- **活动看点（看员工在用 Codex 干什么）**：后台有「Activity」面板，实时显示每条 Codex 请求的**提问摘要 + 时间 + token**；点某个员工那一行可只看他一个人的活动。
  - 抓取粒度由网关 `.env` 的 `ACTIVITY_CAPTURE` 控制：`summary`（默认，截断到约 240 字）/ `full`（最多 4000 字）/ `off`（只记 token 数、不记提问内容）。
  - ⚠️ **合规提醒**：这会记录员工在 Codex 里输入的提示词。请事先告知员工并遵守当地劳动/隐私法规；不需要就设 `ACTIVITY_CAPTURE=off`。

也可以用自动化令牌（`.env` 里的 `ADMIN_TOKEN`）直接调 API，便于脚本/监控：
```bash
curl -H "Authorization: Bearer $ADMIN_TOKEN" http://192.168.1.50:8080/admin/leaderboard
```

## 3.5 上游池：放中转站 API key / 账号 JSON（反代给员工用）

管理者后台有 **「Upstreams — 中转站 / API pool」** 面板。可以把多个上游加进来，网关会把员工的 Codex 请求**反向代理**、按权重轮询分发到这些上游上（不健康的自动跳过）。

**两种加法：**
- **直接填**：名字 + Base URL（如 `https://某中转站/v1`）+ API Key + 权重 → Add。
- **粘 JSON**：支持单个对象、数组、或 `{channels:[…]}`（one-api/new-api 风格）。字段名容错匹配 `base_url/baseUrl/url`、`api_key/apiKey/key/token`。例如：
  ```json
  [
    {"name":"relay-A","base_url":"https://relayA/v1","api_key":"sk-a...","weight":2},
    {"name":"relay-B","base_url":"https://relayB/v1","api_key":"sk-b..."}
  ]
  ```

**行为与要点：**
- Key **只存服务端、永不回显**（后台只显示 `sk-r…cret` 这种掩码）。
- 每个上游有**健康状态**（ok / degraded / down）：连续失败（含 401/403/429）会标记降级/下线并在调度中跳过；恢复后自动回到轮询。
- 池**为空时**回退到 `.env` 里的 `UPSTREAM_*` 默认上游；池**非空时**只用池里的。
- 可随时 disable / delete 某个上游。
- ⚠️ 合规：中转站/账号池化本身可能违反上游服务条款、有封号风险——请自行评估，优先用公司自有合规通道。

> API（管理者会话或 `ADMIN_TOKEN`）：`GET/POST /admin/upstreams`、`POST /admin/upstreams/update`、`POST /admin/upstreams/delete`。

## 4. 离职即失效

两种触发方式，效果都是**该员工所有 Key 立刻失效**（下一次 Codex 请求就 401）：

**A. 手动**（后台点"Revoke"，或调 API）：
```bash
curl -X POST http://192.168.1.50:8080/admin/revoke \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"email":"bob@corp.com"}'
```

**B. 自动**（对接飞书人事）：在飞书后台配置"员工离职"事件回调到：
```
POST http://你的网关/webhooks/feishu/offboarding
```
网关会校验签名（`FEISHU_WEBHOOK_SECRET`）+ 时间戳（防重放），解析出邮箱与「离职」状态后自动吊销。事件体形态兼容多种嵌套（`event.object.email` 等）。

## 5. 推送公司技能（改一次，全员生效）

技能放在服务端的 `skills/` 目录，客户端每次启动自动拉取：

- `skills/AGENTS.md` —— 公司编码规范 / Agent 行为准则（写进员工 Codex 的全局指令）。
- `skills/prompts/*.md` —— 团队斜杠命令（如 `/security-review`、`/write-tests`）。
- `skills/mcp/company-mcp.js` —— 公司 **MCP 工具服务**（如"返回公司编码标准""生成合规脚手架"）。想加工具就改这个文件，全员下次启动即更新；生产建议改成**远程 MCP（URL）**，编辑一次服务端即可，无需动客户端。

> Codex 没有 Claude Code 那种 `skills/` 目录概念，其等价物就是上面三样：`AGENTS.md` + `prompts` + `MCP`。

自测 MCP：`npm run mcp-smoke`。

## 6. 接入真实飞书 SSO（已实现）

飞书 OAuth 授权码流程已经接好，**App Secret 只存在网关**，客户端拿不到。步骤：

1. 在[飞书开放平台](https://open.feishu.cn/)建一个企业自建应用，拿到 **App ID / App Secret**。
2. 开通权限：读取用户**邮箱**（`contact:user.email:readonly`）等。
3. 在应用后台注册**重定向 URL**：`https://你的网关/auth/feishu/callback`。
4. 在网关 `.env` 填：
   ```bash
   FEISHU_APP_ID=cli_xxx
   FEISHU_APP_SECRET=xxx
   FEISHU_REDIRECT_URI=https://你的网关/auth/feishu/callback
   DEMO_MODE=false          # 关掉模拟登录后门
   ```
   （授权/换 token/取用户信息三个端点默认指向真实飞书，可用 `FEISHU_*_URL` 覆盖。）

**登录怎么走：**
- **员工桌面 App / 命令行**：打开浏览器到 `/auth/feishu/start`（带 PKCE 的 `link`+`challenge`），飞书登录后回调到网关 `/auth/feishu/callback`，网关用 code 换 token、取到**已验证邮箱**、签发 Key，App 通过 `/auth/feishu/poll`（凭 PKCE verifier）取回结果。App Secret 全程不出网关。
- **管理者后台**：点「使用飞书登录」→ `/auth/feishu/start?intent=manager`，回调校验是管理者后直接种下会话 Cookie 跳回后台；非管理者被拒 403。

**离线验证**（不需要真实飞书）：
```bash
npm run demo-feishu
```
它用内置的 `mock-feishu` 假 IdP 跑通整条真实代码路径：员工 PKCE 登录、管理者飞书登录、非管理者被拒。

## 8. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 网关拒绝启动，提示 secrets 还是默认值 | 生产保护。跑 `./scripts/setup.sh` 生成随机密钥，或试用时 `DEMO_MODE=true`。 |
| 管理者后台登录后又跳回登录页 | 多半是 `COOKIE_SECURE=true` 但你用的是 http。局域网 http 试用请设 `COOKIE_SECURE=false`；生产请上 HTTPS。 |
| 员工 Codex 报 401 | Key 已被吊销（离职/手动），或员工被标离职。确认后重新登录客户端签发新 Key。 |
| 员工连不上网关 | 确认 Mac mini 防火墙放行 8080，`GATEWAY_PUBLIC_URL`/`--gateway` 用的是员工可达的局域网 IP。 |
| 想换成 Postgres | `gateway/store.js` 是唯一存储层，按同接口替换即可，其余不动。 |
| 上游报错/被限流 | 检查 `.env` 的 `UPSTREAM_API_KEY` 与额度；试用可先用 `--with-mock-upstream`。 |
